# محرر واجهة المتجر البصري

## الهدف
محرر Storefront يجعل محتوى الصفحة الرئيسية والمتجر قابلاً للتغيير من الخادم دون إصدار نسخة جديدة من تطبيق العميل أو التاجر.

## الصلاحيات
- المدير: يرى كل الأقسام العامة وأقسام جميع التجار ويستطيع تعديلها وإعادة ترتيبها.
- التاجر: يرى أقسام متجره فقط ويستطيع تعديلها وإعادة ترتيبها.
- العميل: لا يملك أي صلاحية تحرير.

## ما يمكن التحكم به
كل قسم يحتوي على نوع ثابت (`hero`, `banner`, `category`, `product_grid`, `trend`) وإعدادات JSON منظمة. يدعم محرر الويب الحالي العنوان، الظهور، الترتيب، الصورة، النص الفرعي، نص الزر، والرابط الداخلي أو الخارجي. ويمكن توسيع نفس العقد لإضافة شرائح، دوائر، منتجات وفئات مستهدفة.

## دورة العمل
1. افتح Django Admin ثم Storefront Sections ثم اضغط «فتح المحرر».
2. اسحب الأقسام لإعادة ترتيبها.
3. عدّل العنوان أو الظهور أو إعدادات القسم.
4. استخدم «معاينة» لرؤية شكل القسم داخل إطار هاتف.
5. احفظ القسم.
6. تطبيق العميل يقرأ `/api/home/` ويعرض الأقسام الظاهرة حسب الترتيب.

## قواعد التصميم
- لا تستخدم nested vertical scrolling داخل الصفحة الرئيسية.
- التمرير الرئيسي واحد، والتمرير الأفقي محصور في القوائم التي تحتاجه.
- الصور تستخدم `object-fit: cover` في Hero وبطاقات البنرات.
- كل الروابط تمر عبر whitelist/قواعد التطبيق قبل إصدار إنتاج نهائي.
- أي محتوى حساس مثل الدفع والسياسات لا يدار من Storefront config.

## الاختبارات
توجد اختبارات تغطي:
- المدير يستطيع تعديل قسم عام.
- التاجر يستطيع تعديل قسم متجره فقط.
- التاجر لا يستطيع تعديل قسم متجر آخر.
- محرر الواجهة غير متاح للعميل.
- config يجب أن يكون object صالحًا.
- إعادة الترتيب لا تسمح بضم أقسام ليست ضمن صلاحية المستخدم.

## قبل الإنتاج
- تشغيل `python manage.py check`.
- تشغيل `python manage.py makemigrations --check --dry-run`.
- تشغيل `python manage.py migrate`.
- تشغيل `python manage.py test marketplace`.
- تشغيل `pnpm check`.
- تجربة Web customer وWeb vendor على أحجام هاتف مختلفة.
- تجربة تغيير Hero/Card/Button من Django ثم التأكد من ظهور التغيير على الويب قبل بناء APK.
