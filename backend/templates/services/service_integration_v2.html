SERVICE API CONTRACT

طريقة الربط للخدمات في شبيك

الباقات عنصر داخل Service واحدة للعرض والشراء، والاستعلامات خدمات مستقلة وغير مالية.

← مركز الخدمات

1) الإعدادات

GET /api/v2/services/settings/ GET /api/v2/services/settings/?group=yemen_mobile GET /api/v2/services/settings/<key>/service/

التطبيق يعتمد على المفتاح الثابت للإعداد ثم يقرأ الـ Service المرتبطة به. لا يتم تثبيت service id داخل التطبيق.

2) كتالوج يمن موبايل

GET /api/v2/services/catalog/ GET /api/v2/services/services/<service_id>/

العنصر telecom_plans يعيد السعر والكود ونوع الدفع ونوع الخط والحصة والصلاحية، بالإضافة إلى benefits: الإنترنت، الدقائق، الرسائل، والتقنية عندما تكون مذكورة في بيانات المصدر.

3) شراء / تفعيل باقة

POST /api/v2/services/requests/ Authorization: Token <token> Idempotency-Key: <unique-key> { "service_id": 123, "item_type": "telecom_plans", "item_id": 456, "payload": { "mobile": "77xxxxxxx", "method": "New", "solfa": "N" } }

الخادم يحسب السعر من العنصر نفسه، ويشتق offerkey من كود الباقة. العمليات المدعومة: New / Renew / Remove.

4) يمن نت: ADSL والهاتف الثابت

GET /api/v2/services/catalog/ POST /api/v2/services/requests/

في الفاتورة يرسل المزود صراحة type=adsl أو type=line. أما endpoint الاستعلام في العقد الحالي فهو /post?action=query ولا يعرض type كمعامل للاستعلام ولا يذكر في الاستجابة أن الحساب ADSL أو خط ثابت.

لذلك أصبحت الخدمات داخل شبيك منفصلة محليًا: استعلام يمن نت ADSL واستعلام هاتف ثابت يمن نت. هذا يمنع خلط اختيار العميل، من دون اختراع قيمة لا يدعمها API المزود.

5) متابعة العملية

GET /api/v2/services/requests/<uuid>/
queued / processing

الطلب في طابور التنفيذ.

pending_provider

المزود لم يحسم العملية؛ يتم استخدام فحص الحالة عندما يكون متاحًا.

success / failed / refunded / manual_review

الحالة النهائية تعتمد على المعاملة، وليس على HTTP 200 فقط.

6) الألعاب والبطاقات

عقد المزود يستخدم type لكل خدمة لعبة/بطاقة، مع الحقول مثل playerid وplayername وzoneid وemail وmobile. لذلك تبقى الألعاب والبطاقات منفصلة عن باقات الاتصالات.

7) التنفيذ الآمن

بيانات المزود السرية تبقى على الخادم. تطبيق العميل لا يرسل userid أو password أو token. جميع العمليات تستخدم Idempotency-Key لمنع التكرار.
